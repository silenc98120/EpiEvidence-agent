# Quality Evaluator Skill

## 工作边界

1. 接收一个已经标准化、去重并持久化的同类型文献组。
2. 为每篇文献独立评价相关性、回答问题能力和摘要阶段可见的方法学信息。
3. 核查每项评分、理由和摘要证据，程序从修正后的底层项重算综合分。
4. 排除核查后综合分 `<= 3` 的文章，对保留集合评价 query 覆盖贡献，再由程序稳定排序。
5. 摘要未报告的内容标记为 `unclear` 或 `not_reported`，不得凭空推断。
6. 输出结构化结果；解析失败时返回失败状态，不伪造分数。

摘要阶段只能称为 `preliminary_quality`。用户选择文献并获得全文后，才进入正式的方法学或偏倚风险评价。

## Rubric 路由

根据已经校验的 `study_type` 从固定注册表加载一份研究类型 Rubric：

- RCT：PICO 清晰度、多中心场景、干预/观察时间、统计结果和招募周期。
- 队列：人群/数据源、广义暴露、比较与混杂、结局/时间和统计结果。
- 病例对照：病例定义、对照来源、可比性/混杂、暴露确认和统计结果。
- 横断面：先区分 `cross_sectional_analytical` 与 `cross_sectional_prevalence`，再加载对应 Rubric。
- 诊断准确性：抽样、金标准、数据收集与分析。
- 经济学评价：问题界定、干预与对照、成本与效果、测量与分析。
- 质性研究：研究问题、数据收集、分析、结论与推荐。
- 证据综合：先区分系统评价、Meta 分析、定性系统评价、伞状评价和叙述性综述，再加载对应 Rubric。

各研究类型的可执行摘要规则由 `rubric_registry.py` 按 `StudyType` 固定注册，不把规则堆进本文件，也不使用用户输入构造路径。PRISMA 2020 只能作为报告完整性参考，不能替代偏倚风险工具。

## 摘要初筛评分

每项标准仅根据摘要可见信息标记：`favorable = +1`、`unclear = -0.5`、`not_reported = -1`；确实不适用的项目标记为 `not_applicable`，不计入分母。信息存在但不足以确定是否满足标准时用 `unclear`；摘要完全没有相关信息时用 `not_reported`。不要因摘要没有空间报告全文方法细节而推断研究一定存在偏倚。

每项评分必须同时输出：

- `evidence_quote`：支持该判断的摘要原文；未报告时明确写“摘要未报告”。
- `reason`：说明原文如何支持评分，或缺少什么信息导致扣分。
- `evidence_source`：标记为题名、摘要的具体段落，或显式提供的本地元数据。

## 横断面研究

### 通用规则

1. 识别目标人群、抽样/招募方式、研究场景、暴露或特征、结局及测量时点。
2. 将“暴露”按广义处理，可包括生物、行为、治疗、政策、环境、社会人口学、时间窗口或出生队列等因素。
3. 横断面研究通常不能证明暴露先于结局；若摘要使用因果措辞，必须提示时序不明和因果解释受限。
4. 只评价摘要明确提供的信息，不用全文评价条目反向惩罚摘要。

### 分析型横断面 `cross_sectional_analytical`

从摘要评价以下核心点：

1. **人群与抽样**：目标人群、来源、纳入方式和研究场景是否清楚，样本能否支持拟研究的关联。
2. **暴露测量**：暴露定义、分类或测量方法是否清楚且对各组一致。
3. **结局测量**：结局定义及测量方法是否清楚，是否使用合理、可靠的工具或标准。
4. **混杂控制**：是否识别重要混杂因素，并通过设计或多变量分析进行控制；不要把“匹配”设为必需条件。
5. **统计报告**：是否报告适合关联问题的效应量、精确度指标和必要的调整结果，例如 OR/PR/回归系数及 95% CI。

### 患病率横断面 `cross_sectional_prevalence`

从摘要评价以下核心点：

1. **抽样框与目标人群**：抽样框是否覆盖目标人群，来源、地区和时间范围是否清楚。
2. **招募覆盖**：招募方式、响应率或最终纳入人数是否足以判断选择性参与风险；摘要未报告响应率时按证据缺失处理。
3. **样本量与精度**：样本量是否足以估计目标患病率，是否报告置信区间或其他精度指标。
4. **疾病/状态测量**：病例定义、诊断标准或测量工具是否有效、可靠并一致应用。
5. **患病率统计**：是否提供清楚的分子、分母或样本基数、患病率及 95% CI；复杂抽样时是否说明加权或设计校正。

不要强制患病率研究报告关联效应量，也不要强制分析型横断面研究报告患病率估计；按实际研究问题选择 Rubric。

## 证据综合研究

按以下家族路由：

```text
evidence_synthesis
├── systematic_review
├── meta_analysis
├── qualitative_systematic_review
├── umbrella_review
└── narrative_review
```

Meta 分析是定量合成方法，通常是系统评价的一个亚型，不应与系统评价视为互斥的平行研究设计。

### 系统评价通用标准

对 `systematic_review`、`meta_analysis`、`qualitative_systematic_review` 和 `umbrella_review` 评价；伞状评价应将系统评价而非原始研究视为主要纳入单位：

1. **问题与纳入标准**：研究问题、对象/现象、干预或暴露、对照、结局和研究类型是否清楚，纳入排除标准是否可识别。
2. **检索覆盖**：是否报告主要数据库、检索时间范围及补充检索，使检索范围具备基本可判断性。
3. **质量评价与资料提取**：是否评价纳入研究的质量或偏倚风险，并说明资料提取或复核过程。
4. **合成方法**：合成方式是否与研究问题和数据类型匹配，是否处理研究间差异。
5. **结论支持度**：结论是否与合成结果一致，并考虑证据质量、异质性和重要局限。

### Meta 分析附加标准 `meta_analysis`

在通用标准之外评价：

1. 是否报告效应量、95% CI 和统计模型；固定效应或随机效应模型的使用是否可理解。
2. 是否报告并解释异质性，例如 I²、τ² 或 Q 检验，而不只报告一个合并效应。
3. 在适用时是否进行敏感性分析、亚组分析或 Meta 回归，并避免把探索性结果写成确定性结论。
4. 在纳入研究数量允许时，是否评价小样本效应或发表偏倚；不适用时使用 `not_applicable`，不能机械扣分。

### 其他证据综合亚型

- `qualitative_systematic_review`：评价系统检索、研究质量评价、编码/主题合成过程和解释可信度；不要求合并效应量、I² 或发表偏倚检验。
- `umbrella_review`：除通用标准外，评价所纳入系统评价的质量、评价间研究重叠，以及冲突结果的处理；不要把原始研究数量直接当作独立证据量。
- `narrative_review`：评价主题范围、证据选择透明度、论述平衡性和结论支持度。只有摘要明确报告系统检索、预设纳入标准和规范合成方法时，才可归为系统评价。

PRISMA 及其扩展仅用于判断报告完整性。不得把“遵循 PRISMA”直接等同于低偏倚风险或高方法学质量，也不得因摘要未完整报告 PRISMA 条目就宣称正式质量不合格。

## 批量调用

每组建议 5～8 篇，最多 10 篇。调用时组装：

```text
公共评价规则
+ 当前研究类型 Rubric
+ 组内比较规则
+ 用户 query、Intent、SearchPlan
+ 当前组文章的结构化 JSON
```

一次调用评价一组文章，但必须分别返回每篇文章的相关性、回答问题能力、逐条质量证据、优点、局限和信息缺口。模型不计算归一化质量分、综合分、筛选结果或排序。

## 输出要求

输出必须通过 `skills.quality_evaluator.schema` 中的 Pydantic 模型校验。相关性使用 0～10 分，并转换为 `high`、`partial` 或 `low`。任何分数、判断或结论都必须能追溯到题名、摘要或显式提供的期刊数据。

期刊分区、SCI/JCR、中科院预警等信息由本地数据表提供，不能由模型猜测。

## LangGraph 调用约定

分组节点使用 `Send` 将同类型 UUID 组发给本 Skill；组内依次完成 PostgreSQL hydrate、文章级初筛、核查和程序重算。fan-in 后只将 `> 3` 的候选交给集合覆盖 Agent，再按覆盖贡献分、核查后综合分、发表日期和 UUID 稳定排序。Skill 文件本身不会被 LangGraph 自动执行，运行代码负责 Rubric 注册、Prompt 组装、LLM 调用、结果校验和派生分数计算。

文章级评价运行时加载 [`prompts/core_prompt.md`](prompts/core_prompt.md) 这一份公共系统 Prompt，并安全替换 `__STUDY_DOMAIN__`、`__RUBRIC_RULES__` 和 `__OUTPUT_SCHEMA__`。研究类型细则从固定 Rubric 注册表选择，不为每种研究类型复制完整 Prompt，也不允许使用用户输入构造 Rubric 文件路径。

文章级核查和综合评估使用独立的公共 Prompt：[`prompts/verification_prompt.md`](prompts/verification_prompt.md) 逐项检查评分、理由与原始摘要证据是否一致，并只输出修正建议；[`prompts/portfolio_evaluation_prompt.md`](prompts/portfolio_evaluation_prompt.md) 只对核查后保留的候选集合进行 query-conditioned 覆盖评估。程序根据核查结果重新计算加权综合分，排除 `corrected_composite_score <= 3` 的文章。综合评估不得因为用户没有指定时间或研究类型而强制要求相应覆盖，也不得修改单篇评分。
